# 单 Logo 入口与透明会话面板

版本：2.0 · 2026-09-21。菜单栏入口采用单 Logo；会话卡片、输入框和看板保持原生透明面板设计。

## 1. 菜单栏入口

菜单栏只显示 Chat Bridge 的双眼桥拱 Logo，占位固定 32 pt；图案为 22 × 18 pt 单色模板，由 macOS 适配深浅色。悬浮不展开，也不改变占位。所有 Agent 共用这个入口。

| 操作 | 行为 |
| --- | --- |
| 点击 Logo | 打开上次使用的会话，保留 Agent、项目、会话和草稿。 |
| 再次点击 | 收起浮窗；任务与消息通道继续运行。 |
| Esc／点击浮窗外 | 收起浮窗。 |
| 点击浮窗右上角 ↗ | 打开已有看板，保持会话与草稿。 |
| 看板或设置里选择 Agent | 使用对应 Agent 的原生当前会话；首次消息才创建会话。 |

首次使用时沿用服务的默认 Agent 选择；仅打开 Logo 不调用新建、切换或发送接口。远程消息按现有全局目标规则更新会话，Logo 不另存一套目标。打开浮窗时结束设置弹层、收起主窗口，并切回菜单栏后台模式。

设置保留默认 Agent、显示名称、连接状态与“打开”入口；移除固定／排序菜单栏头像的控件。旧 pinned 偏好保留在持久层，避免破坏已有配置协议，但不影响菜单栏显示。

## 2. 会话与窗口规则

1. 打开、关闭和重复点击 Logo 都不创建 Session、不发消息，也不重置当前草稿。
2. 已有会话不可读或 Agent 未连接时，保留原目标并展示当前状态，不创建替代会话。
3. 浮窗没有标题或工具栏，只保留打开看板的圆形箭头。箭头按菜单栏 Logo 的实际屏幕坐标水平居中，位于 Logo 正下方，不随消息区的内边距偏移。输入框仅保留消息输入和发送，不再显示底部项目／会话选择栏或新建按钮；正常消息交给已配置的智能路由判断目标，失败时提供文本选项。看板的会话菜单仍可用于主动管理目标。
4. 看板与浮窗共用同一服务和草稿；看板打开时显示 Dock 图标，关闭看板后保留菜单栏与后台服务。
5. 应用图标使用雾蓝底的双眼桥拱角色；看板和设置内的 Agent 图标仍使用原有品牌资源。
6. 系统状态按钮直接接收鼠标与辅助功能动作，不再转发到多个头像命中区。

## 3. 轻磨砂面板的视觉边界

**聊天面板采用参考图中的轻磨砂背景，边缘柔和淡出。桌面壁纸或其他窗口仍可透过消息间隙看见，消息卡与输入框使用更明显的局部磨砂。**

| 区域 | 视觉规则 |
| --- | --- |
| 面板背景、消息间隙 | 很淡的跨窗口磨砂，以 24% 不透明度叠加，四周柔和淡出，无矩形外框或窗口大阴影；不显示标题栏。消息滚动区另保留不可察觉的命中层。 |
| Agent 消息卡 | 乳白磨砂卡、柔和落影与轻细白边，在浅色背景上也能区分轮廓；圆角约 22 pt，按内容自然增高，靠左。 |
| 用户消息卡 | 加深的中性灰磨砂底和柔和落影，圆角约 22 pt，浮窗气泡右边缘与输入框右边缘对齐；短消息保持自然宽度，深色模式使用深灰底。 |
| 任务状态／审批 | 放入对应消息卡中，使用明确文字。 |
| 输入区 | 与消息卡一致的乳白磨砂和柔和落影，28 pt 圆角，增加输入留白；保留文本输入和发送操作。 |
| 独立的 Agent 配置弹层 | 普通可读的原生配置面板；不作为聊天消息区域的一部分。 |

建议聊天区域宽 380 pt，可在 320–480 pt 之间适应屏幕；高不超过所在屏幕可用高度的 70%。消息卡最大宽度为聊天区的 84%，单条极短消息不强撑满宽。输入区与当前 Session 绑定，切换后分别保留草稿。

消息间距为 8 pt；消息之间及两侧的空白也能上下滚动。消息滚动区与输入框之间不再添加固定间隔。会话浮层隐藏纵向滚动条，保留鼠标滚轮和触控板滚动。Markdown 宽表格和长代码行使用卡内横向滚动，并保留系统水平滚动指示。

浮窗和看板共用原生 Markdown 消息渲染：支持标题、粗体、斜体、列表、引用、链接、表格、行内代码与代码块；普通单换行保留，代码内容不再次解析。用户消息靠右、AI 回复靠左；看板在气泡内保留身份标签。浅色用户底为中性灰，AI 卡及输入框保持乳白；深色分别使用深灰和原有暗色磨砂。不得将宽表格或长代码行扩展到气泡之外。实际结果见 [消息卡验证](verification/message-markdown-2026-09-19.md)。

浅色模式下 AI 气泡叠加 88% 白色；用户气泡使用 80% 灰阶、94% 不透明度，深色模式使用 20% 灰阶。底部阴影不透明度 7%、模糊半径 12 pt、下移 6 pt；暗色模式使用更深的阴影。浮窗 AI 气泡左边缘、用户气泡右边缘分别与输入框两侧对齐。消息列两侧的 12 pt 阴影空间位于这条对齐线外，浮层两侧和底部分别预留 24 pt 与 30 pt，避免阴影被窗口边缘截断。

消息区顶部使用 48 pt 的模糊与透明度过渡，底部使用 32 pt 淡出，两侧各使用 12 pt 的阴影淡出；滚动命中层也随边缘渐隐。列表首尾预留对应空间，最早和最新消息均能滚到完全清晰的位置。过渡层不拦截鼠标事件，系统减少透明度时关闭顶部模糊。

背景四周通过 `NSVisualEffectView.maskImage` 直接遮罩原生磨砂，使用 32 pt 的透明度过渡并保留完全透明的外缘；不只在 SwiftUI 层遮罩，避免底层磨砂仍产生清晰的矩形范围。

开启系统“减少透明度”时，关闭背景和顶部过渡模糊，将消息卡和输入框替换为可读的实色，不给整个面板补实色背景。亮色／暗色模式分别验证文字对比度，不能把截图中的浅蓝壁纸当作固定使用条件。

## 4. 原生实现方案

- 菜单栏：一个固定 32 pt 的 `NSStatusItem`，原生 button 显示 22 × 18 pt 模板 Logo，整个按钮是同一命中区。[Apple NSStatusItem](https://developer.apple.com/documentation/appkit/nsstatusitem)
- 聊天窗口：使用可接收文本输入的无边框 NSPanel，`isOpaque = false`、`backgroundColor = .clear`，关闭整窗阴影。独立背景磨砂通过低不透明度和羽化遮罩控制，避免变成整块不透明的 popover。[窗口透明属性](https://developer.apple.com/documentation/appkit/nswindow/isopaque)
- 毛玻璃：每条卡片和背景使用 `NSVisualEffectView` 的 behind-window 混合；卡片按圆角裁切，背景羽化边缘。顶部过渡使用 within-window 混合模糊滚动内容，再渐隐到透明，不拦截输入。[Apple NSVisualEffectView](https://developer.apple.com/documentation/appkit/nsvisualeffectview)
- 输入焦点：点击 Logo 展开不覆盖用户剪贴板；点击输入后可正常使用中文输入法，按 Esc 收起。收起面板不停止任务或消息监听。
- 窗口锚定：使用实际 status item 屏幕坐标，在显示器边缘调整面板位置。解锁后重新计算；不将一块屏幕的坐标复用到另一块屏幕。
- 透明只描述渲染，不承诺所有透明像素都能点穿。窗口外点击收起，避免把本机输入误转给后面的其他应用。

面板是同一原生 Session 的视图，不创建一套与 Agent 分离的“本地聊天历史”。通过新增 `readMessages` 加 `observe` 分页加载和更新；本地仅缓存已授权 Session 的用户可见消息。无完整读取能力时明确显示“部分历史”，不能编造内容。

本机发送使用 `origin.kind = desktop`，复用 inbox、任务队列和 Agent 适配器；它不是新增社交通道。该任务的 reply_route 指向本机面板，不自动广播给 iMessage／微信。远程发起的任务继续回原通道，其已授权的同一会话内容也可以出现在本机视图。

输入框仅在已确认打开的 Agent／Session 与当前选择一致时启用。提交携带选择版本；其他入口已经切换时，服务拒绝发送并保留草稿，提示用户重新确认目标。

如果 AX 适配需要激活原生 Agent 窗口，可能使这个面板丢焦点。是否能维持用户在 Chat Bridge 内输入是新的 G0 真机门槛；不能把浏览器里的示意通过当作原生交互已实现，也不在后台连续抢回焦点来掩盖问题。

## 5. 验证边界

对应 [验收清单](verification-checklist.md) 的 U01–U12。交互示意只用于核对单 Logo、会话恢复、看板入口和透明层级；不连接真实 Agent，不修改原生会话。菜单栏系统命中区、跨窗口毛玻璃、窗口焦点和 TCC 权限均须以签名原生包真机验收。
